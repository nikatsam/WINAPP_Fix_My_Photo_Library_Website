Practical answers for Windows photo archives

Good questions.
Careful answers.

Photo backups, exact duplicates, image errors and camera dates can be confusing. These answers explain what the tools can check, what they cannot promise, and when they stop rather than guess.

How can I verify a photo backup when the filenames are different?

Compare file content rather than filenames. Fix My Photo Library computes SHA-256 for the selected photo files, so byte-identical content can match even after a rename or move. A filename match alone is not proof that two files contain the same data.

A backup result is marked verified only when enumeration and hashing complete and every unique source content is present. If a file cannot be read, the report stays incomplete. See the step-by-step photo backup verification guide.

How do I find duplicate photos without permanently deleting the wrong one?

The duplicate tool groups exact byte-for-byte matches. It does not claim two similar-looking photos are duplicates. You review the group, pin the photo to keep, and choose which copies to quarantine.

Quarantine is a separate folder with a recovery manifest. Restore rechecks the expected hash and chooses a new name if the original destination already exists. Read the safe exact-duplicate review guide.

Can Windows tell whether a JPEG or PNG is damaged?

Windows image codecs can fully decode some supported image files and fail on others. A failed decode is a diagnostic signal, not a repair: the tool cannot reconstruct pixels that are missing from a damaged file.

PNG chunk structure and CRC values are checked before decoding. Unsupported codecs, inaccessible files and the image resource limit are reported separately so they are not mislabeled as corruption.

Why is a camera date different from a Windows photo file date?

EXIF capture time is embedded metadata; Windows Created and Modified are filesystem timestamps. They can disagree. EXIF wall-clock dates may also omit a timezone offset, making conversion to UTC ambiguous.

The app previews the date and offset. It does not guess a missing timezone. Date corrections create copies and set the selected Windows timestamps; the original file and embedded EXIF are not rewritten. More detail is in the EXIF photo-date guide.

Are selected photos uploaded or sent to a cloud service?

No photo contents are uploaded by the app. Scans, hashes, decoding, copies and quarantine operations are performed locally. Reports are saved only in the folder you choose. Job history stores a local summary; action journals retain file paths needed for recovery.

See the local-processing privacy summary. Microsoft Store licensing and Windows platform services are separate from photo processing.

Does it support every RAW, HEIC, WebP or animated photo format?

No. Image inspection depends on codecs installed on that Windows PC. Animated frames are checked within a fixed aggregate pixel budget. If a codec is unavailable or a file exceeds the decode limit, the app reports that separately from a failed supported-format decode.

Install codecs only from a source you trust. The app does not download a codec or upload the photo to inspect it.

What should I do if the backup report says “incomplete”?

Do not treat an incomplete scan as verified. Review access-denied, missing, changed-during-scan and cloud-placeholder rows. Make the source and backup available, then run the check again. The app can offer to copy content it confirmed missing, but it rechecks source hashes and never overwrites an existing file.
